Execution Layer

The layer between a target book and a real broker order

Built

The execution layer sits between automated trading strategies and a broker, converting target portfolios into actual orders and reconciling the results. It enforces exposure caps, loss limits, and idempotency through a signed authorisation scheme. No live order has been placed; the system remains in pre-live validation.

The problem

Automated strategies produce target books but cannot safely place orders directly — they need a layer that validates every order against hard limits, reconciles broker responses against intent, and prevents duplicate or untracked executions. The broker API offers no idempotency, no atomic cancel-replace, and partial fills are common. A defect in this layer risks unbounded loss, duplicate orders, or silent drift between intended and actual positions.

What I built

The system is not live. No live order has been placed. An adversarial review with 151 agents found 25 confirmed defects across 11 clusters; all were fixed and re-reviewed by 152 agents, which caught five more defects in the repairs. Test coverage grew from 51 to 78 tests; a mutation gate reverted each fix and required the suite to go red — 5 of 5 caught. Nineteen drills remain unrun. Shadow and paper phases require 15 and 30 clean sessions respectively; zero have been completed.

How it works

The layer runs as a single-session CLI: a dry run prints a session token and the four hashes (settings, code, planned orders, git commit) that a human must sign into an authorisation record. On commit, the same hashes are recomputed and any mismatch refuses the session. Orders are submitted sequentially with per-order collars; a watchdog cancels resting orders on heartbeat loss. Reconciliation verifies five links — intended → submitted → filled → positions → cash — and hard-stops on any rejected, canceled, or expired order. The wrapper drives both lanes through ten exit-code scenarios.

Highlights

  • An adversarial review with 151 agents across 8 lenses and 3 refutation angles each confirmed 25 defects in 11 clusters before any live session.
  • The wrapper script was syntactically invalid due to four em dashes that PowerShell parsed as a smart quote, preventing any execution until fixed.
  • Reconciliation falsely reported success while checking only two of five required links and ignoring rejected orders entirely.
  • A full portfolio exit was unsendable because sell notional was rounded up off the position, causing the commit-time re-check to refuse it.
  • Test coverage increased from 51 to 78 tests and a mutation gate verified 5 of 5 fixes by reverting each and requiring the suite to fail.
  • Nineteen operational drills including HALT cancellation, watchdog cancel-all, and uncertain acceptance resolution remain unrun.
