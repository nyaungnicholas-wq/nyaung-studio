PosterKit

An approved poster set, rebuildable parameter by parameter

Built

PosterKit is a replication engine that captures every parameter of an approved poster set so any poster can be rebuilt or varied programmatically. It works entirely through a design platform's API, using measured specs and a deterministic pipeline to generate new variants without manual design work.

The problem

Design teams often need to produce multiple variants of an approved poster set while maintaining exact visual fidelity. Manual recreation introduces inconsistencies and is time-consuming. The approved posters were built exclusively through a design platform's API, but no record existed of the underlying parameters, making it impossible to regenerate or adjust them programmatically without reverse-engineering each design. This gap forced designers to repeat manual steps for every new variant, increasing the risk of drift from the approved brand standards and slowing down production cycles.

What I built

The repository now holds validated v1 element-level specs for all ten posters (specs/pXX_*_v1.json) and the corresponding plan files (plans/*.plan.json) that together comprise 470 operations. The pipeline successfully reproduces the approved builds and can generate new poster variants programmatically. All specs pass validation and the build process is deterministic, requiring only the builder's final approval.

How it works

PosterKit captures a reference poster by programmatically measuring its colour bands, hero bounding box and layout constants. The engine transcribes this reference into a named-constant CONFIG block and a content dictionary for each poster. A local image composition plus a collision gate is reviewed by the builder before any platform call. The platform build copies the client's carrier design, applies batches in stacking order, and enforces gotchas such as crop re-issue after update_fill, auto re-front of covered carrier elements, knockout-compiled letterform paths, and deferred crop/format markers. Exports are verified at full size and at 150px, with the builder's approval required. Specs are validated against SCHEMA.md and turned into ordered edit-design batches.

~1,350 measured parameters captured across a 10-poster set, every one built through the API
